# 개인정보 처리시스템 점검 자료 취합 사이트 — 요구사항 정의서 (v2)

> 이 문서는 v1 스캐폴드(`claude/privacy-assessment-collection-site-pwsist`)를 다시 검토하여
> 업무 요건부터 새로 정리한 것입니다. **[가정]** 표시는 아직 확정되지 않아 합리적인 기본값으로
> 정한 항목이며, 확정되면 갱신합니다.

## 1. 배경 및 목적

- 개인정보 보호담당 부서는 정기/수시로 기관 내 **개인정보 처리시스템별 안전성 확보조치 이행 현황**을
  점검하고 증적자료를 취합한다.
- 현재는 엑셀 점검표와 이메일로 취합하여 **버전 혼선, 누락 확인, 증적 보관, 집계**에 많은 시간이 든다.
- 목표: 점검표 배포 → 담당자 작성·증적 첨부 → 보호담당자 검토(승인/보완요청) → 결과 집계·내보내기를
  **하나의 웹 사이트**에서 처리한다.

## 2. 사용자 및 역할

| 역할 | 설명 | 접근 방식 |
|---|---|---|
| 관리자(보호담당자) | 점검 항목·대상 시스템·회차 관리, 검토, 결과 집계 | 이메일 + 비밀번호 로그인 |
| 제출 담당자(시스템 담당자) | 배정된 회차의 점검표 작성·증적 제출 | 회차별로 발급된 **전용 링크** (계정 불필요) **[가정]** |

- 검토자를 관리자와 분리하는 세분화된 권한은 범위 밖으로 둔다 (2단계 고려). **[가정]**

## 3. 기능 요구사항

### 3.1 점검 항목(체크리스트) 관리 — 관리자
- FR-01 대분류(영역)와 세부 항목을 등록·수정·정렬·비활성화할 수 있다.
- FR-02 항목마다 **응답 유형**을 지정한다.
  - `STATUS` 이행여부 선택 / `STATUS_FILE` 이행여부 + 증적파일 / `TEXT` 서술형 / `FILE` 파일만
- FR-03 항목별 필수 여부를 지정한다.
- FR-04 평가 기준이 바뀌어도 **진행·완료된 회차의 항목은 변하지 않는다** (회차 생성 시 스냅샷).
- FR-05 최초 설치 시 일반적인 안전성 확보조치 기준의 기본 체크리스트를 제공한다.

### 3.2 점검 대상 시스템 관리 — 관리자
- FR-10 처리시스템(또는 부서)을 등록·수정·비활성화한다: 시스템명, 부서, 담당자명·이메일·연락처, 메모.

### 3.3 회차(취합 캠페인) 관리 — 관리자
- FR-20 회차를 생성한다: 회차명, 설명, 시작일, 마감일, 대상 시스템 선택.
- FR-21 회차 상태: `준비중(DRAFT)` → `진행중(OPEN)` → `마감(CLOSED)`. 마감 후 재개 가능.
- FR-22 진행 중에도 대상 시스템을 추가할 수 있다.
- FR-23 대상 시스템마다 **회차 전용 제출 링크**를 발급하고, 필요 시 **재발급(기존 링크 무효화)** 한다.
- FR-24 회차 단위 진행 현황(미시작/작성중/제출/보완요청/검토완료 건수, 이행률)을 본다.

### 3.4 자료 제출 — 제출 담당자
- FR-30 링크로 접속하여 회차 정보·마감일·점검 항목을 확인한다.
- FR-31 항목별로 이행여부(이행/부분이행/미이행/해당없음), 비고(서술), 증적파일을 입력한다.
- FR-32 **임시저장** 후 다시 접속하여 이어서 작성할 수 있다.
- FR-33 **제출** 시 필수 항목 누락을 검증하고 누락 항목을 안내한다.
  - `STATUS_FILE` 항목은 이행/부분이행 선택 시 증적파일이 1개 이상 필요하다.
- FR-34 제출 후에는 수정할 수 없다. 관리자가 **보완요청**하면 다시 수정·재제출할 수 있다.
- FR-35 회차가 진행중(OPEN)이 아니면 열람만 가능하다.
- FR-36 관리자가 남긴 검토 의견(전체·항목별)을 확인할 수 있다.

### 3.5 검토 — 관리자
- FR-40 제출 건의 응답·증적을 열람하고 증적파일을 내려받는다.
- FR-41 항목별 검토 의견과 전체 검토 의견을 남긴다.
- FR-42 **검토완료** 또는 **보완요청**으로 처리한다.

### 3.6 집계 및 내보내기 — 관리자
- FR-50 회차 결과를 **CSV(엑셀 호환, UTF-8 BOM)** 로 내려받는다: 시스템 × 항목별 응답·비고·첨부 수·검토 의견.
- FR-51 대시보드에서 회차별 제출률과 이행률을 확인한다.

### 3.7 감사 로그
- FR-60 로그인, 회차 상태 변경, 링크 재발급, 제출, 검토, 파일 업·다운로드, 내보내기를 기록한다
  (행위자, 행위, 대상, IP, 시각).
- FR-61 관리자는 감사 로그를 조회할 수 있다.

## 4. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 보안-인증 | 관리자 비밀번호는 bcrypt 해시 저장, 세션은 서명된 HttpOnly 쿠키(8시간) |
| 보안-링크 | 제출 링크 토큰은 256비트 난수, 회차·시스템 단위로 발급, 재발급 시 즉시 무효 |
| 보안-파일 | 확장자 화이트리스트, 파일당 20MB 제한, 웹 루트 밖 저장, 인가된 요청만 다운로드 |
| 보안-로그인 | 로그인 실패 시 동일 메시지, 연속 실패 지연 **[가정: 2단계에서 계정 잠금]** |
| 데이터 보존 | 시스템·항목은 삭제 대신 비활성화하여 과거 회차 기록 보존 |
| 운영 환경 | 기관 내부망 단일 서버 **[가정]**. DB는 SQLite로 시작, Prisma로 PostgreSQL 전환 가능 |
| 사용성 | 한국어 UI, 데스크톱 우선, 모바일에서도 깨지지 않을 것 |
| 규모 | 회차당 시스템 수백 개, 항목 100개 이내 **[가정]** |

## 5. 범위 밖 (2단계 후보)
- SSO/사내 계정 연동, 관리자/검토자 권한 분리
- 이메일 자동 발송(링크 배포, 마감 알림) — 1단계는 링크 복사 후 수동 배포
- 엑셀(xlsx) 서식 내보내기, 회차 간 비교 리포트
- 증적파일 바이러스 검사, DRM 문서 처리

## 6. 확인이 필요한 사항
1. 점검 기준: 안전성 확보조치 기준 고시 기반 기본 항목으로 충분한가, 기관 자체 점검표가 있는가
2. 제출자 인증: 링크 방식으로 충분한가 (추가 인증코드/사내 SSO 필요 여부)
3. 운영 환경: 내부망 여부, 파일 저장소(로컬 디스크/NAS/오브젝트 스토리지)
4. 이메일 발송 필요 여부와 메일 서버
